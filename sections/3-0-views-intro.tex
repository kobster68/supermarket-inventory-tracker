This section presents the architecture as views. Following the fourth edition of
\emph{Software Architecture in Practice} and the SEI Views and Beyond template,
architectural views fall into three categories according to the kind of element they
show (Bass, Clements, and Kazman 333; ``Software Architecture Document Template,'' \S\,Views):
\begin{itemize}[nosep]
  \item \textbf{Module views}, whose elements are implementation units --- the
  system's code structure;
  \item \textbf{Components-and-Connectors (C\&C) views}, whose elements are runtime
  components and the connectors through which they interact;
  \item \textbf{Allocation views}, which map software elements onto the environment
  in which they are built and run.
\end{itemize}
The assignment requires all three. The first draft delivered two of them: the
module decomposition view as the primary view (its decomposition only; later module
views grow from it) and the C\&C view of the runtime system in full as the key view.
This second draft adds the Allocation view in Section~\ref{sec:allocation-view}. The table below classifies each
required view and records its status, so that the required structure is visible even
in a draft.
