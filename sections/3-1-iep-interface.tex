\paragraph{Interface specification.}
\label{sec:iep}
\textbf{Identity, purpose, and version.}
We define version 1.0 of the \IEP, the interface of the \CFE at the \DC.
It connects inventory-event publishers at stores and the \DC to a variable set of
subscribers, including the \CentralMasterInventory, \ShippingOrderGen,
\StoreTrackingClient and \ReportingClient. Its purpose is to accept and durably
record events, confirm receipt, and distribute them to interested subscribers
without making store-local inventory updates wait for the WAN.

\textbf{Provided side.}
The \CFE provides \opPublish for submitting an \InventoryEvent and returns
\opAck only after durable persistence. It provides \opSubscribe and
\opUnsubscribe for selecting source and product-family topics at runtime,
delivers matching events, and provides \opReplay and \opResync for recovery.
Delivery is at least once; event IDs support idempotent processing. The publishing
\Outbox owns the last acknowledged per-source sequence number used for recovery.

\textbf{Required side.}
The \CFE requires a durable event store, a subscriber registry that retains
subscription and recovery state across restarts, an authenticated secure channel,
and a clock for timestamps and timeout measurement. Publishers must supply stable
event IDs and per-source sequence numbers and retain unacknowledged events durably
for retry. Subscribers must receive matching events and process retries
idempotently by event ID. We specify the operations, messages and environmental
requirements in the remainder of this interface definition.

\textbf{Message types and topics.}
We use the following logical records in version 1.0. Field names are case-sensitive;
identifiers are nonempty, opaque strings compared exactly. Transport encoding is
left to the implementation, which must preserve these field types and values.

\begin{description}[nosep,leftmargin=1em,style=nextline]
\item[\InventoryEvent]
\texttt{eventId}: globally unique identifier, unchanged on retry;
\texttt{source}: \texttt{store/<storeId>} or \texttt{dc/<dcId>};
\texttt{product}: stable product identifier;
\texttt{quantityDelta}: signed 64-bit integer in the product's catalogued stock
unit (positive adds stock, negative removes it; zero is invalid);
\texttt{timestamp}: UTC occurrence time in
\texttt{YYYY-MM-DDThh:mm:ss.sssZ} form; and
\texttt{sequence}: positive 64-bit integer, starting at 1 and increasing by one
for each new event from that source. Sequence allocation survives publisher
restarts and is not reset on reconnect; timestamps do not determine event order.
An event ID always identifies the same complete record, including source and
sequence. Retrying an event preserves all fields.

\item[\Acknowledgement]
\texttt{eventId}, \texttt{source} and \texttt{sequence} identify the accepted event;
\texttt{acceptedThrough} is the highest contiguous per-source sequence durably
stored by the \CFE. This is a successful persistence confirmation, not a
confirmation that subscribers have processed the event; failures are errors,
not successful acknowledgements. The \Outbox durably advances its last
acknowledged sequence to \texttt{acceptedThrough} and may prune entries at or
below it. A retry of an already stored event receives a confirmation identifying
the same event and the current \texttt{acceptedThrough} value.

\item[Subscription]
\texttt{subscriberId}: stable client identifier bound to its authenticated identity;
\texttt{subscriptionId}: identifier assigned by the \CFE;
\texttt{sourceFilter}: an exact source or \texttt{*}; and
\texttt{familyFilter}: an exact product-family path, that path followed by
\texttt{/**} for itself and all descendants, or \texttt{*} for all families.
The \CFE stores these selections in its registry. Recovery positions are
maintained separately per subscription and source; a single sequence number
cannot describe progress across multiple sources.
\end{description}

Topics have the logical form
\texttt{inventory/<source>/family/<familyPath>}, for example
\texttt{inventory/store/17/family/food/dairy}. Store, \DC and family-path segments
use letters, digits, hyphens or underscores; slashes separate hierarchy levels.
Product and family identifiers come from the shared product catalog. The \CFE
resolves an event's product to its family path for routing; publishers cannot
choose a different family to bypass access restrictions. A subscription matches
only when both filters match and the subscriber is authorized for that topic.
For example, source \texttt{store/17} and family \texttt{food/**} include dairy
events from store 17 but exclude other stores. Matching uses path segments, so
\texttt{food/**} does not match \texttt{foodstuff}. Additional nesting requires
no message-schema change (\scnref{MOD-2}); topic subscriptions support new clients
without changing publishers (\scnref{MOD-1}, \scnref{INT-2}).

\textbf{Operation contracts.}
The signatures below are logical message syntax, not programming-language calls.
All requests require an authenticated, authorized session using version 1.0.
Common errors are \texttt{INVALID} (malformed fields), \texttt{UNAUTHORIZED}
(identity or scope denied), \texttt{UNAVAILABLE} (required service unavailable),
\texttt{BUSY(retryAfterMs)} (capacity exhausted), and \texttt{TIMEOUT}.
\texttt{retryAfterMs} is a positive integer delay in milliseconds.
A timeout leaves the outcome uncertain; retry with the same identifiers rather
than inventing a new event. Specific errors and successful postconditions follow.

\begin{description}[leftmargin=1em,style=nextline]
\item[\opPublish\texttt{(event)}]
\emph{Meaning/preconditions:} A publisher submits the defined event record for
its authorized source; a new event's sequence must be the next expected value.
\emph{Postconditions:} The \CFE durably stores the event and its ID/sequence
association before emitting \opAck, and makes it available to matching
subscriptions. An identical retry returns another acknowledgement without
creating another log entry; subscribers may still see duplicate deliveries.
\emph{Errors:} Common errors; \texttt{OUT\_OF\_ORDER(expectedSequence)} for a
gap, \texttt{CONFLICT} for a reused ID or source/sequence with different content,
and \texttt{UNKNOWN\_PRODUCT}. Rejected events do not advance the source sequence.

\item[\opAck\texttt{(acknowledgement)}]
\emph{Meaning/preconditions:} This is a \CFE-to-publisher response, not a client
request to mark an event accepted. It contains the defined acknowledgement
record and requires prior durable acceptance of the identified event.
\emph{Postconditions:} The publishing \Outbox records the maximum of its saved
position and \texttt{acceptedThrough} before pruning; repeated or older
confirmations cannot move its position backwards. Subscriber processing is
unaffected.
\emph{Errors:} A receiver rejects malformed, unauthenticated or mismatched
confirmations as \texttt{INVALID} or \texttt{UNAUTHORIZED} without pruning.
A lost response causes a publisher timeout and safe retry of the original event.

\item[\opSubscribe\texttt{(subscriberId, sourceFilter, familyFilter)}]
\emph{Meaning/preconditions:} An authorized client selects the defined topic
filters and establishes a receive channel; both filters must be valid and their
entire requested scope authorized.
\emph{Postconditions:} The \CFE durably registers the subscription and returns
its record plus \texttt{startAfter}, a map from each selected source to its
current highest contiguous sequence (zero if none). Live delivery includes
matching events accepted after these positions. An identical request by the same
client returns the existing subscription and original positions, making retries
safe. Historical delivery is requested through \opReplay; filtered deliveries
need not have consecutive sequence numbers.
\emph{Errors:} Common errors and \texttt{UNKNOWN\_SUBSCRIBER} if the client
identity has not been provisioned. Invalid filters do not create a subscription.

\item[\opUnsubscribe\texttt{(subscriberId, subscriptionId)}]
\emph{Meaning/preconditions:} The authenticated owner removes its subscription.
\emph{Postconditions:} The registry records removal and stops scheduling new
deliveries; already in-flight messages may arrive. Repeating a removal by its
owner returns success, using a retained ownership record. It does not erase the
event log or the client's applied inventory state.
\emph{Errors:} Common errors and \texttt{UNKNOWN\_SUBSCRIPTION} for an identifier
with no active or retained removal record; another client's identifier is denied.

\item[\opReplay\texttt{(role, source, afterSequence, subscriptionId?, events?)}]
\emph{Meaning/preconditions:} \texttt{role} is \texttt{publisher} or
\texttt{subscriber}; \texttt{afterSequence} is a nonnegative, exclusive cursor.
For a publisher, it is the \Outbox's saved acknowledgement position, and
\texttt{events} is an ordered batch of retained events after that position.
Each event is processed under the \opPublish contract and acknowledged only
after persistence; a partial failure reports the first failed event, and retries
may include already accepted entries. For a subscriber, \texttt{subscriptionId}
must name its active subscription, \texttt{events} is absent, and the cursor is
its last durably processed position for this source.
\emph{Postconditions:} Subscriber replay returns matching stored events in
source order through a captured high-water mark, followed by
\texttt{scannedThrough} (that mark). Live delivery for this source is held behind
replay so that the transition has no gap; retries may duplicate events.
The client persists applied changes, duplicate-detection state and its cursor
atomically before advancing it. It may advance through filtered-out events only
after processing all returned events through \texttt{scannedThrough}.
\emph{Errors:} Common errors, publisher errors from \opPublish,
\texttt{UNKNOWN\_SUBSCRIPTION}, \texttt{INVALID\_CURSOR} (ahead of the stored
high-water mark for subscriber replay), or \texttt{HISTORY\_EXPIRED} (required
history is no longer retained). A publisher cursor ahead of the \CFE's durable
position instead requires \opResync; the \CFE must not silently skip the gap.

\item[\opResync\texttt{(role, source, lastKnownSequence, subscriptionId?)}]
\emph{Meaning/preconditions:} An authorized publisher or active subscriber
reconciles recovery positions after a gap or uncertain restart. The sequence is
nonnegative; subscriber requests identify their subscription.
\emph{Postconditions:} Returns \texttt{acceptedThrough},
\texttt{earliestRetained} (the first replayable sequence, or
\texttt{acceptedThrough + 1} for an empty retained log), and a recovery action.
Publishers resend retained entries after the \CFE's position using \opReplay;
subscribers replay after their own durable cursor when history covers the gap.
This operation reports positions; it does not reset sequences, overwrite stock,
or manufacture missing events. If publisher entries have been pruned despite a
lower \CFE position, or subscriber history has expired, it returns
\texttt{RECOVERY\_REQUIRED}: restore a consistent snapshot/backup with its source
positions before replay. Such restoration is an environmental recovery procedure,
not an additional operation. Catch-up is not reported as complete until the gap
has actually been recovered.
\emph{Errors:} Common errors, \texttt{UNKNOWN\_SUBSCRIPTION},
\texttt{INVALID\_CURSOR} for a subscriber position beyond accepted history, and
\texttt{RECOVERY\_REQUIRED} with the available bounds when automatic replay
cannot recover the gap.
\end{description}

\textbf{Shared delivery rules and usage restrictions.}
\begin{description}[nosep,leftmargin=1em,style=nextline]
\item[Initialization and permissions.]
Before accepting traffic, the \CFE restores its log, deduplication records,
source positions and subscriber registry, and verifies that persistence is writable.
Clients authenticate over the secure channel and agree on version 1.0 before
using an operation; unsupported versions are rejected as \texttt{INVALID}.
Each source has one authorized logical publisher: its \StoreAgent, acting through
its \Outbox, or the \DCAgent for \DC events. Concurrent publisher instances must
coordinate sequence allocation and prevent an old instance from continuing after
failover. A store cannot publish for another store or for the \DC.
Read permission does not grant publish permission; authorization is checked on
every request and delivery, including replay (\scnref{SEC-2}, \scnref{SEC-3}).

\item[Ordering and duplicates.]
Local inventory updates, sequence allocation and \Outbox insertion commit
atomically before transmission. The \CFE accepts new events consecutively per
source and serializes delivery per subscription and source; there is no total
order across sources. A sequence gap requires replay of the missing events,
not renumbering or skipping them. Retransmitted older events can recur; subscribers
must ignore already applied event IDs. Deduplication state must survive restarts
and cover the supported retry/replay window. If an older event cannot be verified
against retained identity records, the \CFE rejects it as
\texttt{RECOVERY\_REQUIRED} instead of applying it as new. Reusing an ID or
source/sequence for different content is \texttt{CONFLICT} (\scnref{AV-2}).

\item[Acknowledgements and retries.]
Only durable \CFE persistence permits \opAck; receipt in memory or subscriber
delivery does not. The \Outbox alone owns and durably updates the publisher's
last acknowledged sequence before pruning; connection state cannot replace it.
After \texttt{TIMEOUT}, \texttt{UNAVAILABLE} or \texttt{BUSY}, clients retry with
the same event or subscription identifiers, using exponential backoff with jitter
and a configured maximum delay; \texttt{BUSY} waits at least
\texttt{retryAfterMs}. Publishers retain events until acknowledged rather than
discarding them after a retry limit. Invalid data, permission failures and conflicts
require correction; sequence and history errors use \opReplay or \opResync.

\item[Receiving and recovery.]
A client must complete \opSubscribe before receiving events. On reconnect it
reuses its active subscription and requests \opReplay for each source from its
own durable processing cursor; the publisher's acknowledgement position is not a
subscriber cursor. A new subscription starts at \texttt{startAfter}; earlier
history requires explicit replay. A subscriber persists each applied change and
cursor together, so a crash before commit leads to safe reprocessing
(\scnref{AV-3}). Transport receipt alone never proves application processing.

\item[Backpressure.]
The \CFE bounds incoming batches and per-client delivery queues. When admission
capacity is exhausted, it returns \texttt{BUSY} before accepting a new event;
previously persisted events remain accepted even if their response is lost.
A slow subscriber is paused or disconnected independently, with catch-up served
from the durable log; it cannot block other subscribers or publisher acknowledgements.
Publishers buffer and retry while the WAN or \CFE is unavailable. Local updates
remain independent of the WAN while durable \Outbox capacity remains available;
on exhaustion the store reports a capacity fault and rejects further updates
atomically rather than losing events or promising unlimited offline operation.
Retention limits are explicit: expired history requires recovery, never silent
advancement of a subscriber cursor (\scnref{AV-1}, \scnref{TEST-1}).
\end{description}

\textbf{Variability, capacity, and quality properties.}
The assignment workload is 100 events/s per store for up to ten stores:
1{,}000 new store events/s at the \CFE (\scnref{PERF-1}, \scnref{PERF-2},
\scnref{SCAL-1}). This excludes the \DCAgent's traffic, retransmissions and
subscriber fan-out, which need additional capacity. A 30-minute WAN outage at
that rate requires at least 180{,}000 retained events per store, or 1.8 million
across ten stores. Actual storage must also cover record size, indexes,
deduplication metadata and safety margin; these counts are not byte estimates.
The 99\% local-availability and complete store-to-\DC delivery requirements
motivate local persistence and retry; protocol rules alone do not establish the
availability of the store hardware or database (\scnref{AV-1}, \scnref{AV-2}).

We propose the following initial deployment targets, not additional assignment
requirements or measured results: capacity for 2{,}000 accepted store events/s
during catch-up, including the 1{,}000/s live load; at least 60 minutes of
subscriber replay history (3.6 million events at the live store rate); and
publisher replay batches of 1--100 events. At 1{,}000/s of spare acceptance
capacity, a simultaneous 1.8-million-event backlog takes about 30 minutes to
drain, provided network, storage and subscriber capacity suffice. Retention must
cover both outage and catch-up time; 60 minutes is an initial minimum with no
safety margin in this worst case, so provisioning must increase it for operational
headroom and additional \DC traffic. Retain event identity records for at least
the supported retry/replay period; expired identity history requires explicit
recovery rather than an unverified duplicate acknowledgement.

\opSubscribe and \opUnsubscribe change the active client set at runtime without
changing publishers or restarting the \CFE (\scnref{SCAL-2}, \scnref{MOD-1},
\scnref{INT-2}). There is no fixed protocol limit on client count; each deployment
publishes and enforces its tested concurrent-subscription and queue limits.
Reaching a limit returns \texttt{BUSY}. Adding subscribers increases delivery
work: if all $N$ subscribers select every event, the live store load alone
requires up to $1{,}000N$ event deliveries/s. Capacity and retention are
deployment settings, not a promise of unlimited scaling.

For the initial deployment we propose 95th-percentile publish-to-\opAck latency
of at most 1 second and publish-to-first-delivery latency of at most 2 seconds,
measured from publisher transmission under the live workload, healthy WAN and
storage, within the tested subscription limit and without backlog. These targets
exclude subscriber application processing and do not apply during outages or
catch-up. Load and fault tests must validate them before they are claimed as
achieved (\scnref{TEST-1}, \scnref{TEST-2}).

Delivery to the \DC is eventual, at least once, assuming eventual connectivity,
continued retry, adequate durable capacity and recovery of the \CFE's accepted
log after failure. No accepted event may be discarded merely because a subscriber
is unavailable; subscriber replay is bounded by the declared history window,
after which a consistent snapshot/backup is required. Permanent loss of all
durable copies is outside this guarantee. Idempotent application prevents
duplicate stock changes; the protocol does not promise exactly-once transport.

\textbf{Required environment and security.}
The \CFE needs a transactional, crash-recoverable event store that atomically
commits events, identity records and per-source positions before \opAck, with
backup/restore procedures preserving those positions. Its durable subscriber
registry retains ownership, filters, subscription start positions and removal
records. Subscribers additionally require their own atomic inventory/checkpoint
storage; the registry cannot infer successful processing from socket delivery.
The routing environment supplies the shared product catalog and family hierarchy.

All \IEP connections require encrypted, integrity-protected channels with server
and client authentication; this includes \DC-local clients, not only WAN links.
The environment provisions credentials and source/topic permissions, supports
revocation, and restricts direct database access to authorized service identities
(\scnref{SEC-1}, \scnref{SEC-2}, \scnref{SEC-3}). Wildcards never expand a client's
authorization. The deployment records denied requests and recovery failures
without exposing credentials. A synchronized UTC wall clock supplies timestamps
for diagnostics, while a monotonic clock measures retry and timeout intervals;
clock adjustment must not alter ordering or event identity. Replay depends on
sequence numbers rather than synchronized clocks.
